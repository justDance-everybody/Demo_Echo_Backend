## 🗄️ 数据库问题

### 问题 1: 数据库连接失败

**症状**：
```
sqlalchemy.exc.OperationalError: Can't connect to MySQL server
```

**诊断步骤**：

```bash
# 1. 检查 MySQL 服务状态
sudo systemctl status mysql

# 2. 测试数据库连接
mysql -u root -p -e "SELECT VERSION();"

# 3. 检查数据库是否存在
mysql -u root -p -e "SHOW DATABASES LIKE 'echo_ai_db';"

# 4. 验证 .env 配置
cat backend/.env | grep DATABASE_URL
```

**解决方案**：

```bash
# 方案 1: 启动 MySQL
sudo systemctl start mysql

# 方案 2: 重新创建数据库
mysql -u root -p << EOF
CREATE DATABASE IF NOT EXISTS echo_ai_db CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
GRANT ALL PRIVILEGES ON echo_ai_db.* TO 'your_user'@'localhost';
FLUSH PRIVILEGES;
EOF

# 方案 3: 切换到 SQLite（开发环境）
# 修改 .env
DATABASE_URL=sqlite:///./echo_db.db
```

### 问题 2: 数据库迁移失败

**症状**：
```
alembic.util.exc.CommandError: Can't locate revision identified by 'xxx'
```

**解决方案**：

```bash
cd backend

# 1. 查看当前迁移状态
alembic current

# 2. 查看迁移历史
alembic history

# 3. 重置迁移状态
alembic stamp head

# 4. 强制升级
alembic upgrade head

# 5. 如果仍然失败，重建数据库
mysql -u root -p -e "DROP DATABASE echo_ai_db; CREATE DATABASE echo_ai_db CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
alembic upgrade head
```

### 问题 3: 字符编码问题

**症状**：
```
UnicodeEncodeError: 'latin-1' codec can't encode characters
```

**解决方案**：

```bash
# 修改数据库字符集
mysql -u root -p << EOF
ALTER DATABASE echo_ai_db CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
EOF

# 修改表字符集
mysql -u root -p echo_ai_db -e "
ALTER TABLE tools CONVERT TO CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
ALTER TABLE users CONVERT TO CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
"

# 在 DATABASE_URL 中添加字符集参数
DATABASE_URL=mysql+pymysql://user:pass@host:3306/db?charset=utf8mb4
```

## 🔌 端口和网络问题

### 问题 4: 端口被占用

**症状**：
```
OSError: [Errno 48] Address already in use
```

**诊断**：

```bash
# 查看端口占用
lsof -i :3000
netstat -tunlp | grep 3000

# 查看进程详情
ps aux | grep uvicorn
```

**解决方案**：

```bash
# 方案 1: 杀死占用进程
kill -9 $(lsof -t -i:3000)

# 方案 2: 使用不同端口
export SERVICE_PORT=3001
python -m uvicorn app.main:app --port 3001

# 方案 3: 清理所有相关进程
pkill -f "uvicorn.*app.main:app"
```

### 问题 5: CORS 跨域错误

**症状**：
```
Access to fetch at 'http://...' from origin 'http://...' has been blocked by CORS policy
```

**解决方案**：

修改 `backend/app/main.py`：

```python
from fastapi.middleware.cors import CORSMiddleware

app.add_middleware(
    CORSMiddleware,
    allow_origins=["*"],  # 生产环境应指定具体域名
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)
```

## 🔑 认证和权限问题

### 问题 6: JWT Token 失效

**症状**：
```
401 Unauthorized: Could not validate credentials
```

**诊断**：

```bash
# 检查 token 是否过期
# 使用 jwt.io 解码 token，查看 exp 字段

# 检查 JWT_SECRET_KEY 配置
cat backend/.env | grep JWT_SECRET_KEY
```

**解决方案**：

```bash
# 重新登录获取新 token
curl -X POST http://localhost:3000/api/v1/auth/token \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "username=testuser&password=yourpassword"

# 如果 JWT_SECRET_KEY 改变，所有旧 token 都会失效
# 需要重新登录
```

### 问题 7: 权限不足

**症状**：
```
403 Forbidden: Insufficient permissions
```

**诊断**：

```bash
# 检查用户角色
mysql -u root -p echo_ai_db -e "SELECT id, username, role FROM users WHERE username='testuser';"
```

**解决方案**：

```bash
# 更新用户角色
mysql -u root -p echo_ai_db -e "UPDATE users SET role='developer' WHERE username='testuser';"
```

## 🛠️ MCP 工具问题

### 问题 8: MCP 工具同步失败

**症状**：
```
Error: MCP tool sync failed
```

**诊断**：

```bash
# 1. 检查 Node.js 版本
node --version  # 需要 16+

# 2. 检查 MCP 包安装
npm list -g --depth=0

# 3. 检查 MCP 配置文件
cat MCP_Client/config/mcp_servers.json

# 4. 手动测试 MCP 连接
cd MCP_Client
python test_mcp_connection.py
```

**解决方案**：

```bash
# 1. 重新安装 MCP 包
npm install -g @playwright/mcp minimax-mcp-js @amap/amap-maps-mcp-server

# 2. 重新同步工具
cd Backend
source .venv/bin/activate
python complete_sync.py

# 3. 重启服务
./entrypoint.sh restart
```

### 问题 9: Playwright 工具失败

**症状**：
```
Playwright browser not found
```

**解决方案**：

```bash
# 安装 Playwright 浏览器
npx playwright install chromium

# 如果权限不足
sudo npx playwright install-deps chromium
```

## 🔧 虚拟环境问题

### 问题 10: 虚拟环境依赖冲突

**症状**：
```
ImportError: No module named 'xxx'
ModuleNotFoundError: No module named 'xxx'
```

**诊断**：

```bash
# 检查当前虚拟环境
which python
python --version

# 检查已安装包
pip list

# 检查包路径
pip show fastapi
```

**解决方案**：

```bash
# 方案 1: 重新安装依赖
pip install -r backend/requirements.txt

# 方案 2: 完全重建虚拟环境
deactivate
rm -rf .venv
python -m venv .venv
source .venv/bin/activate
pip install -r backend/requirements.txt
pip install git+https://github.com/modelcontextprotocol/python-sdk.git

# 方案 3: 使用 pip-sync 同步依赖
pip install pip-tools
pip-compile backend/requirements.in
pip-sync backend/requirements.txt
```

## 🌐 API 调用问题

### 问题 11: OpenAI API 密钥无效

**症状**：
```
OpenAI API error: Incorrect API key provided
```

**诊断**：

```bash
# 验证 API 密钥
curl -H "Authorization: Bearer $OPENAI_API_KEY" \
     https://api.openai.com/v1/models

# 检查 .env 配置

```

**解决方案**：

```bash
# 更新 API 密钥
echo "OPENAI_API_KEY=sk-your-new-key" >> backend/.env

# 重启服务
./entrypoint.sh restart
```

## 🧩 Web3 区块链问题

### 问题 13: Solana 钱包连接失败

**症状**：
```
SolanaRPC error: Failed to connect
```

**诊断**：

```bash
# 1. 测试 RPC 连接
curl -X POST https://api.devnet.solana.com \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"getVersion"}'

# 2. 检查钱包地址格式（应该是 44 个字符的 Base58 编码）
echo $SOLANA_WALLET_ADDRESS | wc -c

# 3. 检查私钥格式（应该是 Base58 格式，约 87-88 个字符）
echo $SOLANA_PRIVATE_KEY | wc -c

# 4. 验证 web3-mcp 配置
cat MCP_server/web3-mcp/.env | grep SOLANA
```

**解决方案**：

```bash
# 1. 使用正确的 RPC 端点
# Devnet: https://api.devnet.solana.com
# Mainnet: https://api.mainnet-beta.solana.com

# 2. 重新构建 web3-mcp
cd MCP_server/web3-mcp
npm run build

# 3. 验证钱包地址
# 使用 Solana CLI 验证
solana-keygen pubkey /path/to/keypair.json
```

## 📊 性能问题

### 问题 14: 内存占用过高

**诊断**：

```bash
# 查看进程内存使用
ps aux | grep uvicorn
top -p $(pgrep -f uvicorn)

# 查看详细内存信息
cat /proc/$(pgrep -f uvicorn)/status | grep -i mem
```

**解决方案**：

```bash
# 1. 限制 worker 数量
gunicorn app.main:app \
    --workers 2 \
    --worker-class uvicorn.workers.UvicornWorker \
    --max-requests 1000 \
    --max-requests-jitter 50

# 2. 配置数据库连接池
# 在 .env 中
DATABASE_POOL_SIZE=10
DATABASE_MAX_OVERFLOW=5

# 3. 使用 Redis 缓存
pip install redis
# 配置缓存减少数据库查询
```

### 问题 15: 响应速度慢

**诊断**：

```bash
# 测试 API 响应时间
time curl http://localhost:3000/health

# 查看慢查询日志
mysql -u root -p -e "
SET GLOBAL slow_query_log = 'ON';
SET GLOBAL long_query_time = 1;
SHOW VARIABLES LIKE 'slow_query%';
"

# 分析日志
tail -f /var/log/mysql/mysql-slow.log
```

**解决方案**：

```bash
# 1. 添加数据库索引
mysql -u root -p echo_ai_db << EOF
CREATE INDEX idx_tools_status ON tools(status);
CREATE INDEX idx_tools_type ON tools(type);
CREATE INDEX idx_sessions_user_id ON sessions(user_id);
EOF

# 2. 使用缓存
pip install redis
# 在代码中添加 Redis 缓存层

# 3. 优化查询
# 使用 select_related 和 prefetch_related 减少数据库查询次数
```

## 🔄 应急恢复

### 快速回滚

```bash
# 1. 停止服务
./entrypoint.sh stop

# 2. 回滚代码
git reset --hard HEAD~1

# 3. 回滚数据库
alembic downgrade -1

# 4. 重启服务
./entrypoint.sh start
```

### 从备份恢复

```bash
# 恢复数据库
mysql -u root -p echo_ai_db < /backups/echo/echo_db_YYYYMMDD.sql

# 恢复配置文件
cp /backups/env/.env backend/.env

# 重启服务
./entrypoint.sh restart
```
